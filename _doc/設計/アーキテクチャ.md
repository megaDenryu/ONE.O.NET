# アーキテクチャ

この文書は、ONE.O.NET の層(C# のプロジェクト)と、層の間の参照の向きを定める。生存型の文書であり、プロジェクトの参照を変えたら、この文書も直す。

## 目的

ONE.O.NET は、キャラクターとの会話(認識した発話を文にし、文をキャラクターの声で読み上げる)を、Windows のネイティブの画面で成立させる。この文書の層は、次の3つを互いに知らない形に分けることを目的にする。

- 会話の規則(ドメイン)と操作の手順(アプリケーション)
- 外部との接続(音声認識・音声合成・保存)
- 画面(WinUI 3)

ポートとは、アプリケーションの層が外部に求める働きを表すインターフェースのことである。アダプタとは、ポートを実装し、外部のライブラリやプロセスへ接続するプロジェクトのことである。コンポジションルートとは、全部の実装を組み立てる唯一の場所のことである(`.claude/規約/コード/coding_rule.md` 第2条)。

## 層の定義

全部のプロジェクトは `src/` の下にあり、ソリューションは `OneONet.sln` である。

| プロジェクト | 持つもの | 参照してよい先 | 参照してはいけない先 | 対象の枠組み |
|---|---|---|---|---|
| `OneONet.Domain` | キャラクター・会話・発話・認識結果などのドメインの型 | なし | 他の全部 | `net11.0` |
| `OneONet.Application` | 操作の手順(例: 認識した文を読み上げる)と、外部へのポート | Domain | アダプタ・HostContracts・UI・App | `net11.0` |
| `OneONet.SpeechRecognition` | 音声認識のアダプタ。sherpa-onnx を包む | Domain・Application | 他のアダプタ・HostContracts・UI・App | `net11.0-windows10.0.26100.0` |
| `OneONet.VoiceSynthesis` | 音声合成のアダプタ。CeVIO AI と A.I.VOICE へ接続する。A.I.VOICE へは補助プロセスを通す | Domain・Application・HostContracts | 他のアダプタ・UI・App | `net11.0-windows10.0.26100.0` |
| `OneONet.Persistence` | 保存のアダプタ | Domain・Application | 他のアダプタ・HostContracts・UI・App | `net11.0` |
| `OneONet.HostContracts` | 補助プロセスと本体の間の通信の型 | なし | 他の全部 | `netstandard2.0` |
| `OneONet.AIVoiceHost` | A.I.VOICE 用の補助プロセス(実行ファイル) | HostContracts | 他の全部 | `net48` |
| `OneONet.UI` | WinUI 3 の画面。部品の木を C# のコードで組む(`csharp_coding_rules.md` 第9条) | Domain・Application・SengenWinUI3 | アダプタ・HostContracts・AIVoiceHost・App | `net11.0-windows10.0.26100.0` |
| `OneONet.App` | 起動とコンポジションルート | AIVoiceHost を除く全部 | AIVoiceHost(プロセスとして起動するだけで、アセンブリとして参照しない) | `net11.0-windows10.0.26100.0` |

UI が参照する SengenWinUI3 は、WinUI 3 の部品を C# のコードで構築・配線・更新するための部品のライブラリであり、別の公開リポジトリ(https://github.com/megaDenryu/SengenWinUI3)にある。ONE.O.NET は SengenWinUI3 を git のサブモジュールとして `submodules/SengenWinUI3` に置き、UI は `submodules/SengenWinUI3/src/SengenWinUI3/SengenWinUI3.csproj` を `ProjectReference` で参照する。ONE.O.NET のコミットは、SengenWinUI3 のどのコミットを使うかを記録する。SengenWinUI3 に部品を足したときは、SengenWinUI3 の側でコミットして push し、ONE.O.NET の側でサブモジュールの指すコミットを進めてコミットする(手順は `.claude/規約/リポジトリの地図.md` の「SengenWinUI3 のサブモジュール」)。

## 主要な設計判断

### 判断1: 参照の向きは、プロジェクトの参照でコンパイラに強制させる

各プロジェクトの `.csproj` は、上の表の「参照してよい先」だけを `ProjectReference` に書く。書いていないプロジェクトの型を使うと、コンパイルが通らない。たとえば UI から SpeechRecognition の型を使うコードは、UI の `.csproj` が SpeechRecognition を参照していないため、ビルドで落ちる。境界を破るには `.csproj` を書き換える必要があり、その書き換えは差分のレビューで見える。

Domain・Application・Persistence の対象の枠組みを、Windows を含まない `net11.0` にする。この3つのプロジェクトから Windows の API を呼ぶコードは、コンパイルが通らない。

### 判断2: アダプタは互いを参照しない

アダプタ(SpeechRecognition・VoiceSynthesis・Persistence)は、Application のポートを実装するだけで、他のアダプタを知らない。認識の結果を読み上げへつなぐ手順は Application が持ち、どの実装をつなぐかは App が決める。アダプタ同士が直接つながると、認識の方式を足すたびに音声合成の側を書き換えることになるためである。

### 判断3: 共通の設定は `Directory.Build.props` に置く

`Nullable`・`TreatWarningsAsErrors`・`LangVersion`・`AnalysisLevel`・`ImplicitUsings` は、リポジトリのルートの `Directory.Build.props` が全プロジェクトへ与える(`csharp_coding_rules.md` 第1条)。各 `.csproj` は、対象の枠組み・出力の種類・参照だけを書く。

net48 の AIVoiceHost と netstandard2.0 の HostContracts にも、同じ設定を与える。2026-10-25 に .NET 11 RC2 の SDK で、この2つを `LangVersion` が `preview`・`Nullable` が `enable` のままビルドし、警告0件・エラー0件だった。ただし、この2つでは、C# の新しい機能のうち `union`・`record`・`init` が使えない。同じ日に netstandard2.0 の HostContracts で `record` と `union` を書くと、`record` は型 `IsExternalInit` が無いためにエラー CS0518 になり、`union` は型 `IUnion` が無いためにエラー CS0518 と CS0656 になった。この2つのプロジェクトでは、`sealed class` とコンストラクタと読み取り専用のプロパティで型を書く。

### 判断4: HostContracts の通信の型は、種別の名前と名前付きのDTOの組で表す

HostContracts は netstandard2.0 であり、`union` を使えない。そのため、通信の型を次の形で表す。

1. 通信の1件のメッセージを、種別の名前(文字列)と本体の組にする。本体は、種別ごとに名前を付けた `sealed class` のDTO(例: `読み上げCommand`・`読み上げ完了Event`)である。
2. HostContracts は、種別の名前の一覧(定数)と、種別ごとのDTOだけを持つ。DTOは継承を使わない。
3. 本体の側(VoiceSynthesis、net11)は、受け取った種別の名前から `switch` 式で名前付きのDTOの型を選んで読み、C# 15 の `union` へ変える(`csharp_coding_rules.md` 第10条-2)。知らない種別は、結果型の失敗として返す。`union` は VoiceSynthesis の中だけに置き、HostContracts には置かない。
4. 補助プロセスの側(AIVoiceHost、net48)も、種別の名前で分岐して読む。net48 では `union` と網羅性の検査が無いため、分岐は種別の名前の一覧の定数に対して書き、知らない種別を失敗として返す。
5. 文字列への変換には `System.Text.Json` を使う。`System.Text.Json` のパッケージは netstandard2.0 と net48 にも対応しているため、両側で同じ読み方の設定(`csharp_coding_rules.md` 第10条-1)を使える。パッケージは、最初のメッセージを定義するときに足す。

`System.Text.Json` の型の階層による多態(基底クラスに派生型を登録する方式)は使わない。基底クラスからの継承が要り、`csharp_coding_rules.md` 第8条と食い違うためである。

### 判断5: A.I.VOICE への接続だけを、.NET Framework の補助プロセスに分ける

A.I.VOICE の公式の API のアセンブリは、.NET 11 のプロセスへ読み込むと、古い `System.ServiceModel` への依存のために接続で失敗する。旧版(非公開のリポジトリ RefucteringVoiroStudio)の試作で確かめた事実である。そのため、A.I.VOICE の公式の API は net48 の補助プロセス(AIVoiceHost)から呼び、本体とはプロセスの間の通信でつなぐ。CeVIO AI は、.NET 11 から COM で接続できることを同じ試作で確かめたため、補助プロセスを通さず VoiceSynthesis から直接つなぐ。補助プロセスを要する音声ソフトが増えたら、そのソフトごとに補助プロセスのプロジェクトを足し、HostContracts を共有する。

### 判断6: App は補助プロセスをアセンブリとして参照しない

App と VoiceSynthesis は、AIVoiceHost を `ProjectReference` で参照しない。net11 のプロジェクトは net48 の実行ファイルをアセンブリとして読み込めず、読み込む必要も無い。補助プロセスの実行ファイルを本体の出力へどう置くか(ビルドの順序と、実行ファイルのコピー)は、VoiceSynthesis が補助プロセスを起動する実装を書くときに決める。

## 見込む変更

| 見込む変更 | 新しいコードを足すだけで済むか |
|---|---|
| 音声認識の方式を足す(sherpa-onnx の別のモデル、Windows の音声認識など) | 済む。SpeechRecognition に Application の認識のポートの実装を足し、App で選べるように登録する。Application・UI・他のアダプタは書き換えない |
| 音声ソフトを足す(VOICEVOX など) | 済む。VoiceSynthesis に音声合成のポートの実装を足す。そのソフトが .NET Framework を要するなら、補助プロセスのプロジェクトと HostContracts のDTOを足す。既存の CeVIO AI と A.I.VOICE の実装は書き換えない |
| 画面を作り直す(区画の配置の変更、別の画面の枠組みへの移行) | 済む。UI を書き直すか、UI と並ぶ別の画面のプロジェクトを足し、App の組み立てを替える。Domain・Application・アダプタは画面を知らないため書き換えない |
| 保存先を替える(ファイルの形式、データベース) | 済む。Persistence に保存のポートの別の実装を足し、App の組み立てを替える |
| 補助プロセスとの通信のメッセージを足す | 済む。HostContracts に種別の名前とDTOを足し、VoiceSynthesis の `union` に場合を足す。`union` の `switch` 式は網羅漏れがエラーになるため、扱っていない箇所がビルドで見つかる |
| 操作(アプリケーションの手順)を足す | 済む。Application に手順とポートを足し、UI から呼ぶ。足したポートの実装はアダプタに足す |

次の変更は、既存の内部の書き換えを伴う。

- ドメインの型(キャラクター・会話など)の意味を変える変更は、その型を使う Application・アダプタ・UI を書き換える。ドメインの型は全部の層が知っているためであり、これはドメインの変更として正しい伝わり方である。

## この段階でやらないこと

- ドメインの型・ポート・アダプタの中身は、まだ書かない。最初の操作(認識した文を読み上げる)を作るときに、その操作が要る分だけ書く。
- 補助プロセスとの通信の経路(標準入出力か名前付きパイプか、1件ずつ起動するか常駐させるか)は決めない。A.I.VOICE の接続を作るときに、読み上げの待ち時間を測って決める。
- 参照の向きを `.csproj` の書き換えからも守る検査(許された参照の一覧とビルドの中で照合する検査)は作らない。今は `.csproj` の差分をレビューで見る。
