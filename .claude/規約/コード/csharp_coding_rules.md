# C#コーディング憲法 (C# Coding Constitution)

このファイルは、C#のファイル(`*.cs`)を触る作業に適用する。

本ファイルはC#固有の構文・ツール・命名に関するルールを定める。設計原則(型安全、DI、判別共用体、値オブジェクト等)はコーディング憲法(`coding_rule.md`)に従い、本ファイルはそのC#での書き方を定める。命名の規則の本体は `~/.claude/規約/命名.md` の「操作の言葉と役割の言葉」の節にあり、本ファイルの第13条はC#で変わる点だけを書く。

対象は C# 15(.NET 11)である。C# 15 の `union`(判別共用体を言語機能にしたもの。複数の型のうちどれか1つの値を表す型を宣言する)を使う。

## 第1条：品質担保の義務 (Quality Assurance)

C#コードを変更した際は、ソリューション(`.sln`)のあるフォルダで次のコマンドを実行し、**エラーが0件・警告が0件**であることを確認してからタスクを完了しなければならない。

```powershell
# 実行場所: ソリューション(.sln)のあるフォルダ
dotnet build --no-incremental
```

ビルドには、リポジトリのルートの `global.json` で固定した .NET SDK を使う。`global.json` は `rollForward` を `disable` にする。コマンドの出力を `| tail` のようにパイプへ渡して終了コードを隠さない。

`.csproj` には次の設定を置く。

| 設定 | 値 | 理由 |
|---|---|---|
| `Nullable` | `enable` | null許容参照型(参照型が null になりうるかを型で区別する機能)を有効にし、null の可能性を型に出す |
| `TreatWarningsAsErrors` | `true` | 網羅漏れ(CS8509)・null 漏れ(CS8655)・`await` の付け忘れ(CS4014)を警告のまま残さず、エラーで止める |
| `LangVersion` | `preview` | C# 15 の `union` を使うために要る。`union` が正式な言語版に入ったとき、値を見直す |
| `AnalysisLevel` | `latest-recommended` | .NET SDK 同梱の解析器(コードの規則違反を調べる検査器)のうち、推奨の規則を警告にする |

- `AnalysisLevel` を `latest-all` にしない。2026-10-24 に .NET 11 RC2 で、`union` と3つの `record` だけの6行のコードをビルドすると、`latest-all` では CA1515(公開する必要の無い型を `internal` にせよ)と CA1815(`union` は構造体であり、`Equals` と `==` を上書きせよ)の計6件のエラーになり、`latest-recommended` では0件だった
- **例外**: 既存の大量の警告がある場合、自分が変更したファイルに関して警告を増やさないこと。可能な限り既存の警告の修正を試みること

## 第2条：型安全性

1. `dynamic` と `object` を公開する署名に使わない。外部境界では、第10条のとおり検証済みの型へ読む。
2. 型の絞り込みはパターン(`is`、`switch` 式)で行う。`as` 演算子と括弧のキャスト `(型)値` を書かない。型が合わないときにキャストで逃げるのは設計の歪みの兆候であり、設計を見直す(`coding_rule.md` 第0条-1)。
3. 数値の単位や基準系の取り違えを、値オブジェクト(第4条)で型にする。`int`・`double` を単位の分からないまま境界を越えて渡さない。
4. null 抑制演算子 `!` を書かない。`#nullable disable` と `#pragma warning disable` を書かない。

## 第3条：判別共用体と網羅性

1. **条件分岐は `union` と `switch` 式で表す。** 各場合(variant)は名前付きの型として個別に宣言し、`union` で合成する(`coding_rule.md` 第0条-3、5)。`kind` という文字列やフィールドを持つ1つのクラスで場合を表さない(`判別共用体の失敗パターン.md` の「tagged flat class」)。
2. **`union` の分岐は `switch` 式で書く。** `switch` 文は網羅漏れを調べない。
3. **`union` の `switch` 式に、`_ =>` と `var x =>` の既定の場合を書かない。** 既定の場合があると、新しい場合を `union` に足しても網羅漏れの診断が出ない。
4. **`union` の値に `default` を使わない。** `union` は構造体であり、`default(結果)` はどの場合にも当たらない値を作る。その値を網羅した `switch` 式へ渡すと、実行時に `SwitchExpressionException` になる。`union` を持つ構造体のフィールドを初期化しないまま使わない。
5. 事実の確認: 2026-10-24 に .NET 11 RC2(C# 15)で、3つの場合を持つ `union` に対して1つの場合を書き漏らした `switch` 式をビルドすると、警告 **CS8509**(書き漏らした場合の名前を示す)が出た。`TreatWarningsAsErrors` を `true` にすると、CS8509 はエラーになった。`_ =>` を足すと、CS8509 は出なくなった。`switch` 文では、場合を書き漏らしても診断が出なかった。`union?`(null 許容)を `switch` 式へ渡し、null の場合を書かないと、警告 **CS8655** が出た。
6. 上の事実のとおり、`union` の網羅性を保証するのは、CS8509 と CS8655 をエラーにする第1条の設定と、本条の2〜4である。本条の3と4は言語が検査しないため、レビューで確かめる。機械で検査する案(自作の Roslyn 解析器で `union` の `switch` 式の `_ =>` を禁じる)は、導入するまで本条に書かない。

## 第4条：値オブジェクトと型変換

1. **検証つきの値オブジェクトは `sealed class` で実装する。** コンストラクタを `private` にし、失敗しうる静的生成 `Try〜` は、成功と失敗を `union` の結果型で返す。`bool` と `out` 引数の `TryParse` の形にしない。
2. **検証つきの型に `record` を使わない。** `record` の `with` 式は検証を通らずに値を作れるため、不変条件が破れる。一部を替えた値は、`With〜` メソッドが検証を通して返す。
3. **検証の無い単位の型(ミリ秒、画素数など)だけ `readonly record struct` にしてよい。** 取りうる値に制約が無く、単位の取り違えを型で防ぐことが目的の型である。
4. **型変換は、その値自身のメソッドとして定義する。** `値.To秒()` の形で書き、メソッドチェーンにできるようにする(`coding_rule.md` 第3条-2)。

```csharp
public sealed class 音量
{
    public double 割合 { get; }
    private 音量(double 割合) { this.割合 = 割合; }
    public static 音量の生成結果 TryFrom割合(double 割合) =>
        割合 is >= 0.0 and <= 1.0 ? new 音量(割合) : new 音量の生成Error(割合);
}
public sealed record 音量の生成Error(double 渡された割合);
public union 音量の生成結果(音量, 音量の生成Error);
```

成功の場合は、成功を包む型を作らず、値の型(`音量`)をそのまま `union` の場合にする。`union` は場合の型から暗黙に変換されるため、`new 音量(割合)` をそのまま返せる(2026-10-24 に .NET 11 RC2 で確かめた)。

## 第5条：不在・未設定・使用不可

1. **null を「無し」の意味に使わない。** 「無し」は `未設定 | 設定済み(値)` の `union` で表す(`~/.claude/規約/コード/設計.md` の「不在・未設定・使用不可」)。null 許容参照型の `?` は、外部ライブラリの署名が返す null を受けるときだけ使い、境界で `union` へ変える。
2. 空文字・`-1` などのマジック値を「無し」の意味に使わない。
3. 起動時に先行構築され広く依存される対象は、使用不可のとき、使用時に明示エラーを返す専用の Null Object(何もしない代役の実装)で表す。`null` を渡さない。

## 第6条：構築

1. **失敗しうる非同期構築は、`private` コンストラクタと `static async Task<T>` のファクトリで行う。** コンストラクタの中で `Task` を捨てて走らせない(コンストラクタ内の fire-and-forget が、内部依存の全部に無意味な null 許容を波及させるためである)。
2. 依存はコンストラクタ注入で受け取り、配線はコンポジションルート1箇所に集約する(`coding_rule.md` 第2条)。静的なグローバル状態を持たない。
3. 構築の既定はビルダーである(`設計.md` の「デザインパターンの既定」)。画面の木のように部品の並びが構造そのものである場合は、`new` とオブジェクト初期化子・コレクション初期化子の入れ子の式で書いてよい。

## 第7条：非同期

1. **非同期メソッドの名前の末尾に `Async` を付けない。** 読み手は、メソッドの形を戻り値の型(`Task`・`Task<T>`・`ValueTask<T>`)で読む。
2. **`await` の付け忘れは、CS4014 をエラーにして止める。** 2026-10-24 に .NET 11 RC2 で、`async` メソッドの中で `Task` を返す呼び出しを `await` なしで書くと CS4014 の警告が出た。`async` でない同期メソッドの中の同じ呼び出しでも、CS4014 の警告が出た。`TreatWarningsAsErrors` を `true` にすると、どちらもエラーになった。
3. `async void` は、イベントの受け口(WinUI のイベントハンドラなど、署名が戻り値 `void` に固定された場所)だけに使う。受け口の中で例外を握りつぶさず、`try` で受けて通知する。
4. 意図して待たない `Task` は、変数へ受けた上で、待たない理由を `注意:` で書く。

## 第8条：継承と封印

1. ドメイン層のクラスは `sealed` を既定にする。継承は禁止し、インターフェースと委譲を使う(`coding_rule.md` 第1条-5)。
2. WinUI の部品(`Window`・`UserControl` など)の派生は UI 層なので許す。派生した部品のドメイン判断を持たない。
3. インターフェースの名前は `I` を先頭に付ける。

## 第9条：画面の組み方

1. **画面の部品の木は C# のコードで組む。** 部品の木は、`new` とオブジェクト初期化子・コレクション初期化子の入れ子の式で書く(第6条-3)。XAML(WinUI が読む宣言的な画面記述)で部品の木を書かない。XAML の中に書いた部品は XAML のローダーが引数なしのコンストラクタで生成するため、依存をコンストラクタで受け取れない(`coding_rule.md` 第2条)。また、OneOnet の会話画面とサイドバーは実行中に形が変わる部品が骨格であり、XAML で書くと1つの画面の形が XAML と C# の2か所に分かれる。2026-10-24 に旧版(非公開のリポジトリ RefucteringVoiroStudio)の画面の複合部品154件を全数数えたところ、実行中に形が変わる部品が42件(36%)あり、会話画面とサイドバーでは、部品を親から外して別の親へ付け替える処理と、読み込み後に部品を作って差し込む処理が骨格になっていた。この2つの処理は、XAML の型紙(`DataTemplate`)と表示の切り替え(`Visibility`)では書けない。
2. **XAML は、リソースの辞書(テーマの色・スタイル・コントロールのテンプレート)にだけ使う。** WinUI が要求する `App.xaml` もこれに含める。
3. **データバインディング(`{Binding}`・`x:Bind`)を使わない。** 部品は、構築・配線・更新の順に扱う。構築で部品の木を作り、配線で操作と処理をつなぎ、表示は `更新する(データ)` を明示的に呼んで変える(`coding_rule.md` 第4条「暗黙より明示」)。
4. 同じ形の組み立てが繰り返し現れたら、その形を部品のライブラリへ切り出す。ライブラリは、先に想像で作らず、使われた形から作る。

## 第10条：外部境界

1. **JSON などの外部入力は、境界で名前付きのDTOへ読み、検証済みの値だけを内部へ流す。** 読むのは `System.Text.Json` で行い、設定を厳しくする。

```csharp
private static readonly JsonSerializerOptions 設定 = new()
{
    PropertyNameCaseInsensitive = false,
    UnmappedMemberHandling = JsonUnmappedMemberHandling.Disallow,
    RespectRequiredConstructorParameters = true,
    RespectNullableAnnotations = true
};
```

2. 種別を持つ入力は、種別の文字列から `switch` 式で名前付きのDTOの型を選んで読む。知らない種別は、結果型の失敗として返す。
3. `JsonElement`・`Dictionary<string, object>` などの非構造化データを内部へ流さない。
4. 必須入力の欠落を、既定値で黙って補わない(`coding_rule.md` 第0条-9)。
5. **予期される失敗は `union` の結果型で返す。** 例外は、到達したらバグである状態と、回復できない失敗(ファイルが壊れている、メモリ不足など)にだけ使う。例外の型は、C# の標準の語に合わせ、名前の末尾を `Exception` にする。

## 第11条：コメント

コメントは `coding_rule.md` 第5条に従う。`///` の XML ドキュメントコメントは、公開 API の説明にだけ使い、名前と型で分かることを書かない。

## 第12条：ファイル構成

1. **1ファイルに公開型を1つだけ置く。** ファイル名は型名にする。
2. 型を定義するファイルの名前に、`def` の末尾を付けない(`建物.cs`)。Rust のモジュールと型の名前の衝突(E0255)がC#には無いためである。
3. テストのファイルは `〜Tests.cs`、テストの準備のファイルは `〜Test準備.cs` にする。
4. 1ファイルの行数と分け方は、`~/.claude/規約/コード/分割とコメント.md` の「1ファイル100行の原則と分割の質」に従う。

## 第13条：命名

命名の規則の本体と理由は、`~/.claude/規約/命名.md` の「操作の言葉と役割の言葉」の節にある。本条は、C#で変わる点だけを書く。C#の識別子は大文字と小文字を区別するため、Rust が小文字で書く英語の接頭辞と接尾辞を、C#では大文字で始める。Rust の小文字は rustc の警告(識別子に大文字を使うと出る警告)への対処であり、C#にその警告は無い。

1. **英語の接頭辞は、C# の標準 API(`ToString`・`TryParse`)に合わせて大文字で始める。** `From画素`・`To秒`・`Try計算する`・`With高さ`・`Set高さ`。接頭辞の後ろが英字で始まるときだけ、間に `_` を挟む(`To_Vulkanの矩形`)。
2. **`Try〜` は `union` の結果型を返す。** `bool` を返して `out` 引数に値を渡す形にしない。結果型の失敗側の型の名前の末尾は、`Error` にする(`音量の生成Error`)。名詞にした語の表は `命名.md` に従う。
3. **値を作る静的メソッドは、材料からなら `From〜`、失敗しうるなら `Try〜` で始める。** 検証の無い単純な型は、`new 型(引数)` のコンストラクタ呼び出しで作ってよい。材料なしで作る `new` の関連関数は作らない。C# の `new` が言語の構文だからである。非同期の構築(第6条)は、型名が目的語を担うため、材料が無いときの名前を `作成する` にしてよい。
4. **`Default` トレイト(型の既定値を返す仕組み)に当たるものは、C# には無い。** 型の既定値を返す `既定値()`・`既定()` を作らない。`default` 式(ゼロで初期化した値を作る式)を使わない(第3条-4)。空の値・零の値が要る型は、静的プロパティ `Empty`・`Zero` を持つ。
5. **`〜mut`・`iter〜`・`into〜`・`as〜`・`take〜` は、C# では使わない。** C#には、参照の書き換え可否の区別、所有権の移動、費用なしの型の見なしが無いためである。並びを返すものは、名詞で書き、`IReadOnlyList<T>` か `IEnumerable<T>` を返す。値を別の型へ変えるものは、元の値を使い切るか残すかにかかわらず `To〜` で書く。`as` は C# の演算子でもあり、第2条-2で禁じている。
6. **`Apply〜`・`Step〜`・`Update〜`・`Find〜`・`Calc〜`・`Check〜`・`On〜`・`Read〜`・`Write〜`・`Parse〜`・`Print〜`・`Render〜` は、`命名.md` の表と同じ意味で、大文字で始める。** `Find〜` は、見つからない場合を `union` の `未検出` の場合で返し、null を返さない。
7. **非同期メソッドに `Async` を付けない**(第7条)。
8. **命令と出来事の型の名前の末尾は、`Command`・`Event` にそろえる。** 役割を示す決まった英語の語を使うのは、`命名.md` が `Error`・`List` を英語の決まった語に固定するのと同じ考え方であり、Blitzdrache0 とリポジトリをまたいで名前をそろえるためである。集まりと種類の末尾 `List`・`Set`・`Map`・`Kind` も `命名.md` のとおりにする。
9. **日本語の識別子を基本にする。** 英語の語は `命名.md` の「オーナーが分かると答えた英語の一覧」に載っているものを、1語ずつ使う。

## 第14条：法執行ツール (Enforcement Tool)

次のコマンドにより、本憲法の遵守状況のうち機械で調べられるもの(第1条の設定による CS8509・CS8655・CS4014 のエラー化、Nullable)を監査する。実行場所は、ソリューション(`.sln`)のあるフォルダである。

```powershell
dotnet build --no-incremental
```

第3条の3と4、第2条、第13条は、機械の検査が無く、レビューで確かめる。
